# MCP 与真实外部能力

将配置的外部工具纳入同一权限、审批和恢复体系。

[需求主索引](../feature-map.md) · [技术方案](../designs/integrations.md) · [测试方案](../test-plans/integrations.md)

## 功能说明

操作员可把允许的本地 stdio 工具加入 Agent 工作面。

用户能连接实际数据源与服务，支撑研究、日程、监控等具体工作。

本文描述用户行为和范围；逐项完成状态以主索引为准。当前能力依据代码静态盘点，配置可用性与真实服务/模型质量需分别验证。

## 需求与验收

<a id="f-024"></a>

### F-024 · 受限本地 MCP 工具接入

**需求**：操作员可把允许的本地 stdio 工具加入 Agent 工作面。

**当前实现**：启动服务器、tools/list、tools/call、schema 指纹与工具允许列表已实现。统一经 Code Mode 调用，不提供 exposure 或单工具模式；脚本渐进发现，500 工具目录不预载全部 Schema。Main 和 Worker 均按自己的冻结权限执行。

**边界与剩余工作**：当前子进程受限、无继承凭据/网络；这不是通用远程认证 MCP 客户端。独立 MCP 方法与目录政策已完成托管迁移；当前标准二十三包的完整分发门禁已验收，可独立换版／回退／停用；Host 保留原批准 IO 和 unknown 不重放，旧 Run／Child 保留原方法与目录。契约仍为仓库私有实验级，真实远程认证与供应商 Live 不在此范围。

**验收目标**：真实协议验证发现/调用、漂移拒绝、取消回收与外部效果审批。

<a id="f-025"></a>

### F-025 · 可认证的真实服务接入

**需求**：用户能连接实际数据源与服务，支撑研究、日程、监控等具体工作。

**当前实现**：已有本地 MCP 与配置型 Guest 浏览器基础；GitHub 精确 PR 监听可从 SecretStore 解析 PAT，经 `/user` 验证身份后读取评审及当前提交的 CI。凭据失效、来源失效、限流与协议错误通过安全状态码诊断；替换同一 SecretStore 引用中的 PAT 后下轮重试，无需将密钥复制到状态库。

**边界与剩余工作**：原生 GitHub 监听只读一个明确 PR，不自动签发或刷新 PAT。Composio 应用的具名连接、多账户、托管认证、状态检查及断开入口见 [F-071](#f-071)，Agent 可经既有审批管线执行其工具；这不构成远程 OAuth MCP 或其他原生 Connector 的统一迁移。Web Access 仍复用配置中的实例地址／SecretStore 引用。各真实账户权限、认证恢复及平台结果需 Live 验证。

**验收目标**：在明确服务上完成真实读取/授权动作/失效恢复；无凭据泄漏，审批及 unknown 语义保持一致。

<a id="f-042"></a>

### F-042 · 可靠的环境事件监听

**依赖**：F-025 服务接入与 F-020 渠道。完成状态以主索引为准。

**需求**：用户授权监听实际工作来源后，外部评审、CI 等变化能可靠进入助手，断连恢复后仍能追溯接收与处理情况。

**插件化边界**：`github-pr-followup` 已实现私有实验的实际扫描／展示／轮询和续接配方路径，Host 保留来源、凭据、完整接纳与同 Task 授权；在途票据和已接纳来源保留原版，停用后新扫描不可用。当前默认完整插件组合已包含此包，首次执行独立验证组合用例，无需模型配置；已有选版不重选。组合分发已验收，完整功能兼容与整体验收继续进行；这也不代表通用 GitHub Connector 已实现。边界与清理条件见[独立版本设计](../designs/integrations.md#github-managed-method)。

**当前实现**：显式配置一个 GitHub.com 仓库/PR 后，前台 Web/TUI/Automation 运行时持续读取 review comments、已提交 reviews 与当前 PR head 的已完成 check-runs。完整分页扫描后，将来源版本身份、观察内容、健康及补读成功时间原子保存到 `state.db`，通过 `github status/events` 查看；重复和乱序不重复保存同一来源版本，自身份的评论/评审不回流。

**边界与剩余工作**：未绑定的观察只供本机诊断；本机所有者可将当前精确 PR 显式关联到已有 Task，只有绑定后新观察才交 Main 作为不可信外部证据，再由 Main 判断是否在原目标内追加工作。事件不能创建新 Task 或扩大权限；移除/切换配置与明确撤权持久停止旧绑定，暂时轮询故障保留已接纳观察；GitHub 因果 Main/Task 结果复用 F-020 回原渠道/话题，显式通知偏好仍优先。补读重扫 GitHub 仍保留的当前资源；不保证已删除评论、扫描间消失的中间修改、旧 head 的 CI 或 legacy commit statuses。需要普通 PR Conversation 评论时，所有者把该 Task 的绑定规则设为 `event_kind: issue_comment`；托管包 1.0.2 才读取同一 PR 的评论，按既有观察／自动模式去重、继续原 Task。其他规则及未绑定监听只读原有来源。每类至多接纳 20 页、每页 100 项。当前托管扫描在第 20 页满时额外探测一页：空页确认恰好 2,000 项，非空页报告超限且整批不提交。总规范化内容至多 8 MiB，超过界限显示 `HISTORY_LIMIT` 并保留原成功边界，不能称为完整审计流。

**验收目标**：重复接收不重复接单；断连、重启、乱序和来源权限撤销后按明确边界恢复或停止；监听中断不展示为正常。接收信息不授予任务执行或外部动作权限。

## 如何使用

F-069 已提供搜索与公开网页读取入口，F-067 提供其显式可选后备；F-071 提供 Composio 应用账户与通用工具入口，未接通的服务按明确账户和调用范围另行验收。分类见[术语与登记边界](#术语与登记边界)。F-069 的配置及限制见下方独立条目；以下 MCP 与 GitHub 监听用法只适用于 F-024/F-025/F-042。接入顺序见[个人 Connector 优先级](../feature-map.md#personal-connector-priorities)。

当前在配置中指定本地 MCP 可执行文件、独立目录和允许的工具及权限。启动时纳入冻结注册表，Agent 通过同一工具发现和执行入口使用。

GitHub 监听使用以下显式配置；不要把 PAT 字面量写入 YAML。PAT 需要所选仓库的 Pull requests 和 Checks 读取权限，并能通过 `/user` 返回当前用户身份；SecretStore 使用本地私有凭据文件，并兼容显式环境引用。配置示例同 [config.example.yaml](../../config.example.yaml)。

```yaml
github:
  repository: owner/repository
  pull_number: 123
  credential_ref: env:STEWARD_GITHUB_TOKEN
  poll_seconds: 60
```

启动既有 `web serve`、TUI 或 `automation work` 的生产运行时即持续监听；不要求模型已就绪。`poll_seconds` 默认 60 秒，允许 5–3600 秒。配置变更在重启后生效；移除配置即不启动监听，当前命令不再展示旧范围为活动来源。仅配置 SecretStore 引用，不会自动选择模型。

```sh
steward -config /absolute/config.yaml github status
steward -config /absolute/config.yaml github poll
steward -config /absolute/config.yaml github events
steward -config /absolute/config.yaml github events 101
steward -config /absolute/config.yaml github stop
steward -config /absolute/config.yaml github resume
```

`poll` 执行一次真实只读扫描并返回状态；失败返回非零，同时保留安全诊断。`events` 按 sequence 倒序最多 100 项，下一页传本页最小 sequence；正文最长 16 KiB，截断时明确提示沿来源 URL 读取全文。`status` 区分 `never_checked/checking/healthy/interrupted/stale/stopped/privacy_stopped/not_configured`；超过两倍轮询间隔的旧成功/进行中扫描显示 `stale`，不冒充仍正常监听。CLI 控制可在模型或执行依赖不可用时使用。

`stop` 持久停止并 fencing 在途扫描，普通 `poll` 和重启不能恢复。Forget 同样停止原授权 epoch 的接收，并隐藏旧 epoch 观察；明确 `resume` 才更新接收意图。历史相同 event_key 不会因 resume 重新入库或暴露，只有此后尚未保存的来源版本进入当前观察。它不恢复 Task 或外部副作用。仓库名称对应的不可变 repository ID 改变时 fail closed，不把新仓库当原来源。

### 将 PR 后续反馈关联到已有任务

先配置/成功 `github poll`，确认确切仓库及 PR；再由本机所有者选择已存在、当前隐私作用域内的 Task。`task_epoch` 是所选 Task 当前执行代次，`version` 是 `github binding` 返回的关联版本（首次为 0）。关联只允许 active 或自然完成的 once Task；暂停、取消和用户显式 complete 的当前代次不能绑定。

```sh
steward -config /absolute/config.yaml github binding
steward -config /absolute/config.yaml github bind <<'JSON'
{"task_ref":"task:opaque-ref","task_epoch":1,"version":0}
JSON
```

绑定不回放已经收下的历史观察。上述旧格式绑定明确启用所有新观察。可先按一种事件类型观察匹配结果，再显式启用规则内的自动接续，见 [F-045 规则用法](automation.md#f-045)。接纳的新版本经现有单 Main/Actor 读取 JSON 证据框，判断是否需要 `task_manage append` 继续同一 Task。同一观察只接受一次不同的追加动作；相同来源与相同参数重复请求复用原回执。歧义、超范围、未知副作用或不需继续时，Main 应解释/询问用户，不建立新工作或猜测外部授权。source Main 可读已有授权数据和保存本地产物，不能直接发外部动作、创建 Automation 或写长期 Memory；真正工作交既有 Task Worker 和审批管线。

```sh
steward -config /absolute/config.yaml github unbind <<'JSON'
{"version":2}
JSON
```

使用实际 `github binding` 版本，不固定复用示例值。unbind、监听 stop、Task pause/cancel、用户显式 complete、Forget 和来源撤权会使待处理/正在推理的旧因果失效；恢复监听或普通重启不重新授权已停止的绑定。新用户输入优先建立自身的 Main，保留不可变接收回执，不被旧观察吞并。once Root 自然结束并非人工停止，原绑定可接续；人工 complete 则需要用户明确 append 进入新代次后再重新绑定。未知效果不会因为收到评审而重试。

远程 OAuth MCP 仍未接通；邮件／日历可经 F-071 配置 Composio 账户。真实账户权限、业务结果及 GitHub 保留历史的补读范围仍需独立验证。

## 集成术语和当前接入

本节按明确的外部应用／服务登记 connector，每项拥有主索引中的独立 ID，不把一个平台的完成扩展到另一个平台。当前用户是希望延续个人研究、工程交付及生活安排的本机所有者。委托过某项工作只证明场景需求，不能直接推出需要某个 connector。

### 术语与登记边界

本节统一 Steward 的产品术语：**插件扩展能力，连接器接入外部服务，连接绑定具体账户或实例，技能提供工作方法，工具执行具体操作。** 术语用于与外部助手的能力扩展、应用连接和技能概念对应，不承诺安装包格式或运行时兼容。

| 术语 | 产品定义与示例 | 当前归属与边界 |
| --- | --- | --- |
| 插件 Plugin | 能力扩展包，可包含工具、技能、连接器及相关界面；可只包含一个技能或连接器，也可组合多种能力 | Web Access（F-069）及 Connected Apps（F-071）为内置插件；独立安装／启停等生命周期归 F-070，已提供 Go 协议与 CLI 基础，业务迁移待完成 |
| 连接器 Connector | 将明确外部应用／服务的数据、资源与允许操作接入 Steward 的集成能力，如 Tavily、Exa、SearXNG、Gmail、GitHub、高德 | 按外部系统登记与验收；服务协议适配器是工程实现，账户／实例的连接状态、凭据引用与撤销由平台管理 |
| 连接 Connection | 某个连接器或模型接入使用的具体账户／服务实例及其授权状态，如具名 SearXNG 实例、绑定 Tavily 凭据的服务连接、模型账户 | 平台配置与 SecretStore 持有凭据引用；Composio 应用账户在 F-071 按别名管理，其他原生连接仍用各自配置；公共服务可以无需个人账户授权 |
| 技能 Skill | 完成特定任务的可复用方法、指令与资源，如研究步骤或邮件整理方法 | 读取与经验管理见 [Skills](skills-experience.md)；加载技能不授予新的工具或连接权限；Web Access 的研究配方当前是代码组合，尚无独立可安装 Skill |
| 工具 Tool | Agent 可调用的具体操作，如搜索、读取网页或续读证据 | 工具声明进入既有 Registry／Code Mode／Executor；实际调用受角色、冻结权限和具体动作审批约束 |

插件可以组合多个连接器，也可以不依赖外部服务；同一连接器可供不同插件复用，并对应多个连接实例。F-071 提供 Composio 应用的多账户入口，已提供协议包清单，尚无跨插件连接选择器。安装插件、授权连接和批准具体动作分别处理；移除插件不隐式删除共享连接或凭据，断开连接也不等于卸载插件。

连接器提供外部系统的业务操作，工具将具体操作暴露给 Agent，插件可组织工具与组合工作方法。只读系统和公共数据服务也可以有连接器，不要求每项都有 OAuth、写操作或后台同步。工程模块的实际依赖与职责见[集成设计](../designs/integrations.md#f-069--web-access-的最小组合方案)。

以下类别另按自身能力边界管理：

| 类别 | 示例 | 在本规划中的归属 |
| --- | --- | --- |
| 执行通道 | 浏览器操作、文件读取、SSH 命令执行 | Agent 执行能力，不因可操作外部系统就各算一个业务 connector |
| 模型能力／供应商 | 图片生成、视觉理解、语音识别 | 模型能力接入；“图片生成”本身不是一个外部业务系统 |
| 数据导入 | 聊天导出、会话 JSONL、健康 XML | 一次性迁移或文件读取，不等于连接了来源应用的账户／业务接口 |
| 协议 | MCP | 可承载工具和资源的协议，不等于某个 connector，也不限定其业务边界 |

例如 Gmail 连接器的目标操作包括查邮件、读线程、保存草稿和发送，高德连接器的目标操作包括地点、路线和天气查询；这些操作的接通范围由各 feature 单独验收。MCP 的工具／资源划分见[官方服务端概念](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/docs/docs/2026-07-28/learn/server-concepts.mdx)，不把一个 MCP server 或一个 tool 机械等同于一个业务 connector。

未实现的外围能力保留原 ID，见[暂缓条目](#暂缓的外围能力)。

F-069 Web Access Plugin 是用户统一使用的搜索／网页访问接入，内部组合已允许的服务适配器和正文读取能力；它不是一个新的外部系统，不与 F-046/F-067/F-068 重复计算供应商数量。服务条目独立维护兼容性，插件负责选择链路、组织工具及统一交付。原生搜索属于当前模型适配器；本地解析是可复用处理机制；摘要／来源核查是插件内研究配方，不另算 connector。安装插件、连接账户与执行工具是三个独立动作。

Web Access 与 Web Extract 的托管迁移及适用产品门禁已完成验收；原二十三包的完整分发门禁已验收，当前30包组合仍待验收。简单 HTML、图片转换与 MIME／模式分派已进入 Web Access 隔离服务；Node／PDF 的独立 `web-extract` 组件已接原 Run／Child、配置／撤权与原 Artifact 管线，真实候选算法参与独立验证，解释器与方法资源随原图保存；所有者可用 Go 离线封存入口打包原脚本及依赖，原 runtime 锁文件保持原字节。旧 Run 保留原版本，插件不能更改原 URL、来源时间或授权；新分派缺少原图 decoder 时明确失败，不回 native。标准分发已装配这两个组件，首启选择完整标准组合并固定原解析资源；已有选择／停用保持不动。现有 Web 功能的迁移包含独立换版／回退／停用、历史引用、真实业务及兼容清理；外部服务与质量缺口仍按 F-069 单独登记。

<a id="f-046"></a>

### F-046 · Tavily 搜索与网页正文

**需求与依据**：用户交给助手原文查找、技术调研、帖子核验和商品比较后，能得到带来源的可核查结论。需求明确且重复出现；本项保留为 Tavily 的独立接入，免费优先的 Exa MCP／SearXNG 候选分别见 F-067/F-068，不再将 Tavily 预定为唯一或首个默认服务。

**当前实现**：F-069 已有自建 Search API 适配器及协议回归；独立 Extract 正文操作和真实账户 Live 待完成。

**目标与边界**：首版支持搜索及指定公开 URL 正文提取，保留来源 URL、读取时间、可用的发布时间、截断与提取失败。区分原文、转载和搜索摘要；不自动登录受限站点，不将私有资料拼入公共查询。认证与用量走 SecretStore 及现有额度机制。[Tavily Search](https://docs.tavily.com/documentation/api-reference/endpoint/search) 与 [Extract](https://docs.tavily.com/documentation/api-reference/endpoint/extract) 是不同操作，搜索命中不表示正文已读。

**验收目标**：找到指定原文并读取后引用；无结果、过时内容、正文不可达、限流、取消与正文中的恶意指令均有真实边界，不能把摘要当成全文或将第三方内容当成授权。

<a id="f-067"></a>

### F-067 · Exa MCP 搜索候选

**需求与依据**：为个人研究提供低设置成本的公开网络搜索，优先验证免密钥方案。[Exa 官方说明](https://exa.ai/blog/best-web-search-mcp-servers)确认其托管 MCP 可免密钥、按免费限流使用，不能推导为无限免费或长期服务保证。

**当前实现**：F-069 内已实现免密钥 Exa 托管 MCP 搜索，经初始化和工具发现后调用 `web_search_exa`。在显式 `source_order` 中允许 Exa，或兼容配置 `exa_fallback: true` 时启用；支持固定源，不支持高级过滤。当前为部分完成，真实中文质量与服务长期可用性仍待验证。

**候选范围与边界**：先接固定官方服务的公开搜索、来源结果及服务实际返回的内容，不复制 Pi 的配置、会话或订阅认证。实际工具名称／schema 需在目标服务核实，不能依赖插件中硬编码的旧名称。高级过滤不支持时明确说明限制；只有显式允许时才可退为查询文字提示，并区分硬过滤、本地筛选与检索提示。带 API key 的付费／额度路径需独立授权和用量边界，不因免费限流自动切到付费调用。

**目标验收与未决项**：无密钥真实查询可返回可打开来源；429、不可用、协议／工具变化、取消和不完整内容准确呈现。缺正文不能称为已读全文；严格时间／域名条件不能静默降级。真实中文／英文任务、时效和成本需要对比后再选默认服务。

<a id="f-068"></a>

### F-068 · SearXNG 自托管搜索候选

**需求与依据**：个人搜索可选择已有或自行部署的搜索服务，减少对单一商业 API 的依赖。SearXNG 是聚合搜索服务，软件开源不代表机器、维护或所有上游均无成本。

**当前实现**：F-069 已有自建 JSON Search API 适配器及 HTTP peer；未选择或部署真实实例，实例位置、上游、网络和维护责任待确认。

**候选范围与边界**：只连接所有者明确选择的实例，通过[官方 JSON 搜索接口](https://docs.searxng.org/dev/search_api.html)获得标题、URL、摘要和可用的时间信息。实例认证经 SecretStore 引用；受信搜索服务端点与任意网页 URL 的访问范围分别校验。不自动使用随机公共实例或部署服务；不少公共实例禁用 JSON，接口可达也不能证明所有上游正常。时间／域名能力按实际引擎验证，不把查询运算符当作统一硬过滤保证。

**目标验收与未决项**：对明确实例查询并保留来源；403 格式未启用、429、上游错误／部分结果、错误 JSON、取消及重定向正确诊断。缺少结果字段不能直接转成零命中，跨 origin 不转发认证头；部署与中文覆盖的 Live 验证不由适配器存在替代。

<a id="f-069"></a>

### F-069 · Web Access Plugin

**需求与消费者**：Main／Task Worker 用同一 Registry／Code Mode／Executor 完成公开研究、网页读取和证据续读。插件编排、connector 服务协议、工具契约及平台状态管理均由 Steward 自建，不安装外部 agent SDK、不复制插件实现或类型，也不接管其他助手的会话与凭据。

**归属**：按[统一术语](#术语与登记边界)，Web Access 是随程序分发、独立版本化的托管业务插件，组织搜索、读取、问答和证据工具。Exa／SearXNG／Tavily 是外部搜索服务连接器，各自的协议适配器实现服务调用；当前 Tavily 仅接 Search，Extract 尚未实现。实例／凭据绑定与当前模型连接由平台提供。原生搜索属于模型适配能力，本地解析属于内容处理能力；研究配方当前为代码组合，尚未提供独立可安装 Skill。本功能已迁入 F-070 的独立插件生命周期；HTML／PDF 方法由同属 F-069 的 Web Extract 组件独立换版。

**执行能力与历史兼容**：`builtin__web_search` 支持单查询或最多八个查询、显式 provider、域名条件、时间偏好、来源正文及摘要工作流。`builtin__fetch_content` 支持最多八个公开 HTTP(S) URL 的 readable／raw／answer 模式：本地提取 HTML Markdown、文本、PDF 和图片；问答使用当前冻结模型，并保存原始提取证据。`builtin__get_search_content` 从返回的 `responseId` 续读或 exact／case-insensitive／fuzzy 查找；分页和片段坐标是 UTF-8 字节偏移，不拆分字符，fuzzy 按顺序匹配忽略空白的词组。`builtin__source_check` 收集来源、原文片段及哈希供人工判断；有来源为 `unclear`，无证据为 `missing-evidence`，不声称自动裁定支持或反驳。保留的 `builtin__web_fetch` 提供原有公开 HTML／文本读取。

**选路与配置**：默认按已配置 SearXNG → 当前账户原生搜索 → 显式启用的 Exa → 已配置 Tavily 顺序尝试。零命中成功即停止；认证拒绝、预算阻断、无效响应和取消不换源。临时不可用、限流和明确不支持可进入下一来源。显式 provider 不换源，也不能绕过冻结的 `source_order` 目的地限制；不并发广播或自动部署／选择公共实例。

```yaml
web_access:
  source_order: [native, exa]
```

只使用账户原生搜索可设 `source_order: [native]`。默认不启用 Exa；兼容配置 `exa_fallback: true` 时将其加入默认顺序。自托管服务设 `searxng_url: https://search.example`，可选 `searxng_secret_ref` 指向 SecretStore 的 Bearer 凭据。Tavily 使用 `tavily_secret_ref`，例如显式 `env:TAVILY_API_KEY` 环境引用；密钥只从 SecretStore 解析，不写进配置或继承给正文提取进程。SearXNG 使用[官方 JSON Search API](https://docs.searxng.org/dev/search_api.html)，Tavily 使用[官方 Search API](https://docs.tavily.com/documentation/api-reference/endpoint/search)。改变来源、凭据引用、解析程序或锁定依赖会改变冻结工具身份，旧 Run 不静默套用新配置。

**账户与费用**：当前模型为 Steward `openai_account` 时使用自身 Sign in with ChatGPT 的 `api.openai.com/v1/responses` 托管搜索，要求实际完成的搜索事件；端点地址不意味着 API Key 计费。批量原生查询、网页问答及摘要各自经独立交换、预算、用量和撤权 fence，保留主模型快照。只发送本次查询或明确请求处理的证据，不发送聊天历史、附件或工具目录。当前账户路径已有真实账户／Main／Code Mode 搜索验收；其他账户、模型与订阅政策仍按实际能力验证。外部搜索费、服务额度与 token 用量分开，不宣称已知总费用或无限免费。

**过滤保证**：原生搜索将包含域名传给 hosted tool；排除域名和返回来源列表由本地严格筛选，带域名条件时不把未筛选的供应商回答当成结果。SearXNG 的时间范围依赖实例／引擎，Tavily 的时间范围由服务处理；日期没有统一硬保证。Exa 当前窄 MCP 工具不能承诺高级过滤，带域名／日期条件时明确不支持，不把条件降级为查询文字却声称成功。

**提取与持久化**：网络访问在 Go Host 校验并固定公开 DNS，重定向重新检查，拒绝内网／保留地址、非标准端口及任意本机路径；不带浏览器登录或账户认证。提取进程只收到本次有界文档，使用独立 HOME／TMPDIR、不继承密钥且禁用解析器网络请求。HTML 通过通用 Readability／Defuddle／Turndown 解析，PDF 通过 unpdf 本地提取；未配置解析程序时 HTML 可用基本正文提取，PDF 明确不可用。标准安装自动装配 `web-extract.mjs`；显式安装可指定绝对路径 `extract_command`／`extract_script`。下载至多 8 MiB，PDF 至多 200 页，文本至多 5 MiB，证据集至多 24 MiB；超限明确失败。图片限 32M 像素并转为最大 2000×2000 JPEG；至多八个媒体附件，与状态和工具终态原子提交。

全文、来源、时间与证据片段保存在当前作用域 Artifact，`responseId` 就是该 Artifact 引用，不依赖进程缓存。问答不会覆盖原文；摘要 `summary-review` 返回 `reviewRequired` 的未批准草稿。查找只读已保存证据；已完成工具结果重放不重新访问网络，未知的搜索／提取不自动重复计费。所有内容均为不可信证据，不能授予权限；可见性、Forget、发布和取消继续由既有机制负责。

**明确缺口**：未实现独立 OpenAI API Key／私有订阅端点、其他搜索供应商、Tavily Extract、登录网页／浏览器升级、GitHub clone、YouTube／本机视频或交互摘要编辑器。GitHub 服务闭环仍归 F-047；普通公开网页可尝试本地提取，不能称为已读取完整仓库。免费服务限流、中文质量、SearXNG 真实实例和 Tavily 真实账户分别验收，F-069 仍登记为部分完成。本机 fake-IP 将公网 DNS 改为保留地址时会安全拒绝，没有为代理关闭保护。

### F-071 · Composio 应用目录与账户连接

**需求与消费者**：为日常生活和工作预备广泛的外部应用接入，用户按需连接账户。Composio 提供应用与工具目录、托管认证及执行协议；Steward 自建适配器，继续拥有账户绑定、工具权限、审批和恢复机制。

**入口与使用**：使用者在 Settings → Apps 浏览应用、Connect 和管理账户；部署者在 Settings → Resources → App connection service 配置 Composio。Apps 只展示应用与账户操作，不展示项目初始化或服务设置入口；服务未就绪时，在具体账户连接操作处禁用 Connect 并以问号说明。部署者从 Resources 管理服务。分类选择后直接筛选，无脚本时保留提交按钮，不显示项目密钥表单。发现首页展示固定顺序的 Gmail、Google Drive、Google Calendar、GitHub、Slack、Notion 六个精选应用，随后按沟通与日程、文档与知识、任务与规划、开发、设计、商务及个人生活提供每组最多六项的名称排序预览。精选不在首页其他组重复；“查看全部”打开完整编辑分组，包含该组的精选应用。精选和分组条目不代表该项目已验证支持。搜索和“全部应用”可分类筛选并逐页浏览 Composio 的完整原生应用目录，不限于编辑名单；没有项目时继续浏览内置目录。

目录按用途分组（邮件沟通、日历任务、文档存储等），不提供“热门”榜单；采用双列列表（手机单列），每项含应用 logo、名称、一行用途及连接／管理入口。左侧“已连接的应用”列出账户绑定；点击应用打开详情，集中显示账户状态、额外账户、重连和断开，无 JavaScript 时使用原生详情页。推荐列表中的 65 个应用随包附带从 Composio 官方取得的品牌 SVG；实时目录保留 `meta.logo`，新应用图标经 Steward 同源缓存显示。未核实的推荐名称不作为已支持的应用展示，项目完整目录仍以实时结果为准。

1. 创建 Composio 项目，将项目 API key 配置为 Steward 进程的 `COMPOSIO_API_KEY` 环境变量并重启。未显式配置项目引用时，服务通过 SecretStore 自动使用 `env:COMPOSIO_API_KEY`，无需进入设置页保存；变量缺失时仍可浏览内置目录。自定义 SecretStore／环境引用及认证覆盖仍在 Resources → App connection service 中 Verify and save，已有显式引用优先，凭据失效也不改用默认项目。自动读取不会连接应用或创建账户工具；只有用户 Connect 才记录绑定。
2. 选择实时目录中的应用，点击 Connect，浏览器打开授权页面。首次连接自动使用账户别名；已有可用账户时，通过 Add account 填写 `work` 等独立别名。系统自动选择该应用已为 Tool Router 启用的最新自定义认证配置，否则使用 Composio 托管认证；部署者可以在服务设置中覆盖配置 ID，Apps 不接收该参数。授权页面及同意范围由 Composio／原服务展示。
3. 在新标签页完成授权后，Apps 每五秒自动检查新账户，至多十分钟。只有确切账户、用户和应用匹配、未被禁用且状态 ACTIVE 的连接才启用；远端禁用后检查会将本地连接标为失效并撤下工具；Refresh status 保留为无脚本与网络异常时的手动入口。弹窗被拦截时使用 Open authorization page，未过期链接会复用，不重复创建账户；链接只保留在服务进程和页面内存中，重启或过期后需要显式 Reconnect。一个应用可以连接多个具名账户；公开免认证应用也需要用户显式启用。
4. 新的 Main／Worker 能通过 Code Mode 搜索该账户的操作，再传入确切工具版本、描述指纹和 JSON 参数执行。当前所有远程业务操作均需要 Steward 逐次审批；不依据供应商的 read-only 提示自动放宽授权。新增连接只用于新建的冻结能力快照，旧 Run 不自动获得新账户。
5. Disconnect 先持久关闭 Steward 的使用权限，再尝试 Composio 的上游撤权及记录删除。无法确认原服务已撤权时明确提示；迟到的授权结果不能复活旧绑定。失效或未完成的授权可使用 Reconnect 新建绑定，旧绑定保持断开；已正常工作的账户不能被重连动作替换。

**凭据与费用**：本地仅保存项目凭据引用、安装独有 user ID 和账户标识／状态；OAuth token 由 Composio 托管。Composio 会处理所连接应用的数据及工具参数，需在创建项目、授予权限时了解其服务条款与用量。工具执行沿用现有审批与 Artifact 保存；网络中断或响应不确定时登记 unknown，重启也不自动重复远程动作。未启用 Composio instant、workbench、代理或批量执行能力。

**插件迁移边界**：标准32装配独立的工具、目录、账户、Logo 与界面包。工具方法／指引／分页，目录查询／分类／分组／排序／账户事实投影，账户连接意图／认证配置／链接创建／检查／关闭／重连／设置行，以及 Logo 来源和缓存策略均有托管路径。界面包持有规则、组合、全部普通页面及客户端／样式；这些既有子项分别保留原控件、旧图和引用语义。

### 任务的专用邮件转发地址（F-042）

本机所有者可以给进行中的一个 Task 分配随机收件别名。需要已有的收件域名和能按信封收件人调用本机程序的转发器。通过 `make build` 构建的 `bin/plugins/task-mail` 是可选解析包。运行以下命令启用它，然后把返回的地址登记到自己的转发器。

```sh
steward mailbox enable-plugin /absolute/path/to/bin/plugins/task-mail
steward mailbox bind "$task_ref" forward.example.org
```

转发器把未修改的邮件交给标准输入，并传入已接纳的信封收件人和该次投递的稳定 ID。重试须复用 ID 和原始邮件字节。读取、翻页与关闭使用以下入口。

```sh
steward mailbox receive "$envelope_recipient" "$delivery_id" < message.eml
steward mailbox messages "$task_ref"
steward mailbox messages "$task_ref" "$last_sequence"
steward mailbox close "$envelope_recipient"
```

解析器接纳最大 256 KiB 的 UTF-8 或 ASCII 纯文本邮件，支持常见传输编码及编码主题。成功结果包含任务和文本 Artifact 引用。可用 `steward artifact open "$artifact_ref"` 查看。转发器应把非零退出按自身的退信／重试策略处理。关闭、任务暂停／终止或 Forget 后，旧地址停止接纳；需要继续时按当前任务状态重新绑定。收件域名、MX 和远端转发器由域名所有者管理。
