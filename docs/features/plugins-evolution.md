# 功能插件与受控自进化

所有者希望功能以完整、可独立验收的插件持续改进，由稳定的 Host／Guardian 托管版本、资源、执行与恢复，避免每次改进都升级整个程序或破坏在途工作。

[需求主索引](../feature-map.md) · [技术方案](../designs/plugins-evolution.md) · [测试方案](../test-plans/plugins-evolution.md)

功能包与受控演化统一遵循已实现基础能力的 [steward-rsi-plugins 协议](../designs/steward-rsi-plugins.md)。RSI 为 Recursive Self-Improvement（递归自我改进）；业务能力与改进工具可以迭代，可信底座的裁定边界保持独立。

## 功能说明

拆分原则是 **feature 原子＋可独立无损自迭代**：一个包覆盖一条完整功能闭环，按需携带工具、方法、事件、设置、视图和资源。独立迭代允许声明依赖，但不能要求同步修改其他插件的私有代码或状态。无损指保留数据、因果关系、在途执行与已发布引用，不承诺任意版本可以立即卸载或无条件继续执行。

Agent Loop 保持稳定；其余功能按上述原则逐步提取。Host／Guardian 是托管底座：保留执行权、审批、凭据、原始历史、冻结快照、持久回执、验证、激活与恢复，不能由普通插件自行改写。底座升级仍走独立工程与发布流程。

当前已提供 0.1 实验协议的 Go SDK、CLI 管理、隔离调用、版本绑定、候选验证与激活基础；当前默认40个包覆盖现有业务的已提取实现，逐项真实调用、兼容、生命周期与清理状态以[迁移清单](plugin-migration-status.md)为准；现有业务迁移验收已完成。自动生成／晋级／部署闭环不在本轮代码重构范围。

## 需求与验收

<a id="f-070"></a>

### F-070 · 功能原子插件与无损生命周期

**架构约束**：all in 插件覆盖全部现有与新增业务；固定 Loop 与最小可信 Host／Guardian 保留不可下放机制。新增业务走所属托管插件，原生兼容仅限明确历史／迁移边界。完成判定要求实际业务职责提取及当次旧代码清理，部分策略或 native 代理不能代表整个功能完成；详细规则由[全量插件化设计](../designs/plugins-evolution.md#plugin-first)统一维护。

**需求与消费者**：所有者能独立安装、验证、启用、停用、换版和移除完整功能包；开发者能单独验证一个包的变更。插件声明版本、依赖、资源、权限需求和状态兼容范围，Host／Guardian 托管其生命周期。插件与账户／实例连接分别管理，安装、连接授权和具体动作审批相互独立。

**当前实现**：`plugin` CLI 与 Go SDK 提供封存、安装、准备、独立 Owner 验证、激活／回退／停用／退役、状态 CAS、事件、依赖调用及独立 stop／resume／quarantine。默认40个包已提取现有业务的实现、政策与适用的模板／CSS／文案／浏览器程序。Host／Guardian 保留固定 Loop、权限／审批、凭据、权威事实、事务、隐私、版本固定、效果接纳与恢复。实际逐项迁移及历史消费者边界统一见[迁移清单](plugin-migration-status.md)和[当前包边界](../designs/plugins-evolution.md#候选功能包清单)。

**边界与剩余工作**：现有业务迁移与当次替代代码清理已完成；具名旧 Run、原引用、旧控制部署与直接嵌入消费者仍保留必需的历史解释器及删除条件。Go SDK 保持实验级，不承诺公共市场、任意业务零 Host 修改接入或永久兼容。通用贡献挂载、引用感知的自动 GC 与自动化平台配额未在本轮新增；共享连接、凭据和权威数据不随插件停用／卸载删除，凭据仍只由 SecretStore 管理。

**验收目标**：

- 安装 → 验证 → 就绪 → 接收新工作 → 排空旧工作 → 退役可查询、可恢复；停用和卸载不隐式删除状态或共享连接。
- 插件独立版本化；锁定实现、配置、依赖和资源的组合版本，经验证后原子切换新工作的选择，不能混用未验证组合。
- 旧 Run／Child 树、在途调用、后台事件和已发布交互保留原版本及必要资源，或经过显式验证的兼容迁移；旧引用不失效，未知副作用不重发。
- 新增插件或连接不扩大旧快照权限；撤权、取消及 Forget 优先于旧版本恢复。安全撤销可以停止旧派发，不以“无损”维持不安全执行。
- 失败可保持原组合；不可逆状态迁移不伪装成可回退更新。普通插件不能绕过 Host 的事务和授权契约。

<a id="f-072"></a>

### F-072 · Host／Guardian 托管的受控自进化

**需求与消费者**：所有者能在明确授权范围与预算内，让助手根据失败、纠正或可重复改进机会，提出功能插件的新版本，隔离构建验证，按已授权策略自动切换，并在退化时停止新派发、恢复已知可用组合。所有者能追溯变化依据、验证、部署和回退结果，也能独立停机。

**当前实现**：已有插件候选提案、操作员独立政策、真实隔离用例验证、绑定环境的裁定、原子激活／审计与独立停机；获得授权的插件可以通过 SDK 提案，但不能自批或激活。回退可针对旧目标重新验证并激活。自动构建／生成、效果监测、自动回退、费用预算与长期质量闭环尚未接通。[F-023](skills-experience.md#f-023) 的方法经验仍由原 CLI Reviewer 驱动；诊断 Trace 不代替可靠演化审计。

**边界与剩余工作**：F-023 继续持有方法经验学习，F-070 持有插件托管与版本生命周期，本项负责“改进提案 → 验证 → 授权策略裁定 → 激活 → 观察／回退”的自动闭环。候选可以改变插件策略和实现，不能修改固定 Loop、Host／Guardian 权限、验收标准、审计事实或底座发布规则。Guardian 当前实现为 Host 内受保护的裁定代码与存储，未部署成独立服务。macOS 尚无与 Linux 相同的硬内存上限，不据此宣称任意自生成代码可自动上线。

**验收目标**：

- 候选绑定确切基线、内容／依赖哈希、来源、目标、预算和预期效果；构建与验证不接触生产凭据，不在生产重放外部动作。
- Guardian 使用独立持有的用例与不可放宽的安全门槛，校验真实候选上的结果；候选不得自评自批，构建成功不代替行为和质量验证。
- 既有权限内、预授权且可回退的更新可以自动激活；扩权、换账户、不可逆迁移和底座变更保留明确审批／发布边界。自动激活不隐含发行程序版本的授权。
- 审计可靠关联候选、基线、验证环境、结果、裁定、组合版本、激活／回退和受影响执行；关键写入失败时不继续激活。隐私撤销后清理或隔离派生内容，不能以审计为由保留已撤销正文。
- 验证失败、预算耗尽、监测退化、Guardian 不可用或进程崩溃时有确定停止／恢复结果；人工停机优先。回退只恢复后续工作的版本选择，不撤销已发生的外部副作用。

## 如何使用

使用方式见[协议操作入口与可构建示例](../designs/steward-rsi-plugins.md#操作入口)。安装不自动启用，操作员显式创建图与独立政策、验证候选后再激活。首版工具为无生产网络／凭据的纯计算插件；自动演化策略不默认启动。既有方法使用与 Reviewer 操作仍见 [Skills 与经验沉淀](skills-experience.md)。
